# パスワード管理ツール練習サイト

パスワード管理ツール（iPhone の「パスワード」アプリなど）で、パスワードの「保存」と「自動入力」を練習するための Web サイトです。パスキーの作成と、パスキーでのログインも練習できます。

公開先: https://password-manager-practice.pages.dev （Cloudflare Pages）

## できること

- 会員登録 → ログアウト → 自動入力でログイン → 答え合わせ → アカウント削除
- 複数のアカウント（この端末で5つまで）と、パスワードの変更: 管理ツールの項目を取り違えたり、上書きしたりせずに、保存・更新・自動入力する練習ができます。
- 答え合わせ: 入力されたパスワードが、登録したときのものと同じかを判定します。違うときは、考えられる理由（以前のパスワードが入力された、別の練習用アカウントのパスワードが入力された、など）を表示します。
- パスキー: パスワードでログインしたあと、マイページでパスキーを作成し、パスキーでログインする練習ができます（自動入力の候補から選ぶか、「パスキーでログイン」を押す）。パスキーを削除したあとに、管理ツールに残ったパスキーでログインしようとして失敗する場面も試せます。
  - 対象: iPhone の「パスワード」アプリ、Android の Chrome（Google パスワード マネージャー）
- 全部リセット: この端末の練習データをすべて消します。

## しくみ

- HTML・CSS・JavaScript だけの静的なサイトです。サーバ側の処理、フレームワーク、ビルドの仕組みはありません。
- 登録と照合は、ブラウザの中の JavaScript が行います。**パスワードはどこにも送信しません。**
- パスワードそのものは保存せず、PBKDF2（HMAC-SHA-256、ソルト付き、反復60万回）のハッシュ値だけを、その端末のブラウザ（localStorage）に保存します。
- パスキーは、本来サーバが行う確認（チャレンジの作成、公開鍵の保存、署名の確認）を、ブラウザの中で行います（`public/js/passkey.js`。WebAuthn と Web Crypto を使い、外部のライブラリは使いません）。保存するのは公開鍵だけで、秘密鍵はパスワード管理ツールの中にあります。
- 練習サイトに記録のないパスキーでログインしようとしたときや、パスキー・アカウントを削除したとき、全部リセットのときは、Signal API（Chrome 132 以降、Safari 26 以降）で管理ツールに知らせます。管理ツールによっては、そのパスキーが自動で削除されたり、隠されたりします。
- セキュリティ設定（`public/_headers`）で、外部への通信や、ほかのサイトへの埋め込みを禁止しています。

## ファイル構成

```
public/            … 公開されるファイル
├── index.html     … はじめに（注意事項・練習データ・全部リセット）
├── signup.html    … 会員登録
├── login.html     … ログイン
├── mypage.html    … ログイン後（答え合わせ・ログアウト・パスキー・アカウント削除）
├── change-password.html … パスワードの変更
├── css/style.css
├── js/
│   ├── store.js        … 練習データの保存・読み出し
│   ├── auth.js         … 登録・照合（ハッシュ化）
│   ├── passkey.js      … パスキーの作成・確認（署名の確認）と、管理ツールへの知らせ（Signal API）
│   ├── input-check.js  … 入力のしかた（自動入力か手入力か）の推定
│   ├── ui.js           … 画面表示の共通処理
│   └── index.js / signup.js / login.js / mypage.js / change-password.js … 各画面の処理
└── _headers       … セキュリティ設定（Cloudflare Pages の形式）
tests/             … 自動テスト（公開されません）
├── unit/          … Node で、保存・登録・照合・パスキーの確認の処理を確かめる
└── e2e/           … ブラウザ（Playwright）で、画面の流れと表示を確かめる
```

## 公開のしくみ

- Cloudflare Pages と連携しています。ビルドはなく、`public` フォルダをそのまま配信します。
- `main` ブランチにマージすると、本番に公開されます。`main` は保護されており、プルリクエストを通してしか変更できません。
- ほかのブランチを push すると、確認用URL（`https://<ブランチ名>.password-manager-practice.pages.dev`。`/` は `-` に変わります）が作られます。確認用URLは、アクセス制限により本人しか開けません。

## 手元で動かす

Node.js が入っていれば、Cloudflare の公式ツール wrangler で、本番に近い形で動かせます（`_headers` の設定も反映されます。Cloudflare へのログインは不要です）。

```sh
npx wrangler@4.149.0 pages dev public --port 8788
```

ブラウザで `http://localhost:8788` を開きます。

- パスワードのハッシュ化に使う Web Crypto と、パスキーは、HTTPS か `localhost` で開いたときにしか使えません。スマホからパソコンの IP アドレス（`http://192.168.x.x` など）で開くと、登録やログイン、パスキーは動きません。
- `localhost` で作ったパスキーは、そのパソコンのブラウザのパスワード管理ツールに保存されます。確かめ終わったら削除してください。
- ポート番号が変わると、別のサイトとして扱われ、練習データは引き継がれません。
- サーバを動かすマシンにブラウザがない場合は、`--ip 0.0.0.0` を付けて起動し、別のパソコンから SSH のポート転送でつなぎます（例: `ssh -N -L 8788:<サーバのIPアドレス>:8788 <ユーザー名>@<マシンのIPアドレス>`）。そのパソコンで `http://localhost:8788` を開けば、`localhost` として扱われるので、そのまま試せます。
- スマホの表示は、パソコンのブラウザの開発者ツールを開き、デバイスモード（Chrome・Edge では Ctrl+Shift+M、Mac は Command+Shift+M）にすると確かめられます。パスワード管理ツールの動きは、パソコンのブラウザのものになります。

## 自動テスト

`tests/` フォルダで実行します。公開されるのは `public` フォルダだけなので、テストのファイルやパッケージは公開されません。

```sh
cd tests
npm ci                                       # 初回のみ
npx playwright install --with-deps chromium  # 初回のみ（ブラウザと、必要なシステムのパッケージ）
npm test                                     # すべて実行
npm run test:unit                            # Node のテストだけ（追加のパッケージは不要）
npm run test:e2e                             # ブラウザのテストだけ
```

- **Node のテスト**（`tests/unit/`）: 登録・照合・パスワードの変更・削除・全部リセットの判定と、パスワードそのものを保存しないことを確かめます。ハッシュ化は本番と同じ回数で行うので、数秒かかります。
  - パスキー: Web Crypto で作った鍵と署名（`tests/unit/fake-authenticator.js`）で、作成と確認の処理を試します。書き換えた署名、ほかのチャレンジ・オリジン・サイトのもの、ほかのアカウントのものを通さないことも確かめます。
- **ブラウザのテスト**（`tests/e2e/`）: wrangler で `public` を配信し（ポート 8789）、ヘッドレスの Chromium で、スマホとパソコンの画面の幅で確かめます。
  - 画面の流れ（会員登録 → ログアウト → ログイン → 削除、パスワードの変更、複数のアカウント、全部リセット）と、答え合わせの表示
  - パスキー（`passkey.spec.js`）: Chromium の仮想の認証器を、管理ツールの代わりに使います。作成、ボタンと自動入力でのログイン、重ねて作らないこと、削除したパスキーでの失敗、Signal API の呼び出しを確かめます（Signal API は、実際には呼び出さずに記録します）。
  - 管理ツールが読み取る `autocomplete` 属性、セキュリティ設定（`_headers`）の反映
  - 入力欄が先に見える並べ方、「タップ」と「クリック」の言い分け、横にはみ出さないこと
  - どのテストでも、コンソールのエラー（CSP の違反を含む）が出ないこと
- **パスワード管理ツールの動き（保存の提案、自動入力、パスキーの保存の確認や候補の出方）は、自動テストでは確かめられません。** 実機（確認用URL）で確かめます。

## 注意

- **本物のパスワードは使わないでください。** 練習用のユーザー名（例: `renshu-01`）と、パスワード管理ツールが提案するパスワードを使います。
- 練習データは、その端末のそのブラウザの中にしかありません。ほかの端末やブラウザからはログインできません。
- Safari は、しばらく使わなかったサイトのデータを自動で消すことがあります（使った日で数えて7日間）。パスワード管理ツールに保存した項目は消えません。
- 練習が終わったら、パスワード管理ツールから練習用の項目（パスワードとパスキー）を削除してください。
- パスキーは、作ったときのサイト（ドメイン）でしか使えません。確認用URLや `localhost` で作ったパスキーは、本番のサイトでは使えないので、確認が終わったら削除してください。
